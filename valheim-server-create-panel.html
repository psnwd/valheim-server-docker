QUICK START
Get your Valheim server running in under 10 minutes

Prerequisites

  • A Linux VPS (Ubuntu 22.04+ recommended) with 2 vCPU / 4 GB RAM / 40 GB SSD
  • Root SSH access to the VPS
  • A free UploadThing account for backups
  • Ports 2456–2457 UDP open on your firewall

5-Step Deploy

1 — Install Docker on your VPS

sudo apt update && sudo apt install -y docker.io docker-compose-v2 curl jq
sudo systemctl enable --now docker
sudo usermod -aG docker $USER

2 — Upload your generated files

scp docker-compose.yml valheim-backup.sh root@YOUR_VPS_IP:/opt/valheim/
ssh root@YOUR_VPS_IP
cd /opt/valheim && chmod +x valheim-backup.sh

3 — Open firewall ports

sudo ufw allow 2456:2457/udp
sudo ufw allow 22/tcp
sudo ufw enable && sudo ufw reload

4 — Start the server

docker compose up -d
docker compose logs -f   # Watch startup (takes 2–5 min first time)

5 — Register hourly backup cron

crontab -e
# Add this line:
0 * * * * /opt/valheim/valheim-backup.sh >> /var/log/valheim-backup.log 2>&1
Done! Connect in-game via Add Server → enter YOUR_IP:2456. You can also find your server by name in the public server browser if you set it to public.
DOCKER GUIDE
Understanding the container setup and configuration

Why Docker?

The lloesche/valheim-server-docker image is the gold standard for self-hosted Valheim. It handles automatic game updates, graceful server restarts, and keeps your world data safely in named Docker volumes separate from the container.

Volume Layout

VolumePurpose
midgard_valheim_configWorld saves, player data, server config — back this up!
midgard_valheim_dataValheim server binaries (re-downloadable, no need to back up)

Host path: /var/lib/docker/volumes/midgard_valheim_config/_data/

Environment Variables

VariableDescription
SERVER_NAMEDisplay name shown in server browser
WORLD_NAMEMust match your save file names exactly
SERVER_PASSMin 5 chars. Cannot equal SERVER_NAME
SERVER_PUBLIC1 = visible in server list, 0 = private
UPDATE_CRONCron for auto-update checks. Default: every 15 min
TZServer timezone for logs (e.g. Asia/Singapore)
BACKUPSSet false — we use our own UploadThing backups

Common Docker Commands

CommandAction
docker compose up -dStart server in background
docker compose downStop server gracefully
docker compose restartRestart container
docker compose logs -fStream live server logs
docker compose pullPull latest image version
docker stats midgard_valheimCPU / RAM usage live
Important: Every time the game updates, the server must also update or players can't connect. The Docker image handles this automatically via UPDATE_CRON.
BACKUP SYSTEM
Automated hourly uploads to UploadThing

How It Works

The valheim-backup.sh script runs on a cron schedule. Each run it compresses your world files into a timestamped .tar.gz, requests a presigned upload URL from UploadThing's API, uploads the archive, then cleans up old local copies keeping only the last 3.

Backup Script Flow

  1. Reads world files from Docker volume at /var/lib/docker/volumes/midgard_valheim_config/_data/worlds_local
  2. Creates valheim_WORLDNAME_YYYYMMDD_HHMMSS.tar.gz in /tmp/valheim_backups/
  3. Calls UploadThing POST /v6/uploadFiles to get a presigned URL
  4. Uploads the archive via HTTP POST to the presigned URL
  5. Logs the UploadThing file key for recovery reference
  6. Removes all but the 3 newest local archives

Setup

# 1. Set your API key persistently
echo 'export UPLOADTHING_API_KEY="sk_live_YOURKEY"' >> /etc/environment
source /etc/environment

# 2. Test the script manually
/opt/valheim/valheim-backup.sh

# 3. Watch the log
tail -f /var/log/valheim-backup.log

Restoring a Backup

# 1. Download the archive from UploadThing (get URL from your UT dashboard)
wget -O /tmp/restore.tar.gz "https://YOUR_APP_ID.ufs.sh/f/FILE_KEY"

# 2. Stop the server
cd /opt/valheim && docker compose down

# 3. Extract into the volume
tar -xzf /tmp/restore.tar.gz \
  -C /var/lib/docker/volumes/midgard_valheim_config/_data/worlds_local/

# 4. Restart
docker compose up -d
Tip: UploadThing free tier gives you 2 GB storage. Each backup is typically 1–10 MB. At hourly backups you can keep 200–2000 snapshots before hitting the limit.
SAVE FILES
Uploading and managing your Valheim world data

Save File Locations

OSPath
Windows%AppData%\..\LocalLow\IronGate\Valheim\worlds_local\
macOS~/Library/Application Support/unity3d/IronGate/Valheim/worlds_local/
Linux~/.config/unity3d/IronGate/Valheim/worlds_local/
Server/var/lib/docker/volumes/midgard_valheim_config/_data/worlds_local/

Required Files

Each world consists of exactly two files. For a world named MidgardWorld:

  • MidgardWorld.db — The actual world data (terrain, buildings, items)
  • MidgardWorld.fwl — World metadata (seed, name, timestamps)
Warning: The world name in WORLD_NAME must match these filenames exactly (case-sensitive on Linux). A mismatch will generate a new empty world.

Copying Saves to VPS After Upload

After uploading via this panel, run on your VPS:

# Get your file URLs from UploadThing dashboard
# Then download directly into the Docker volume:
docker run --rm -v midgard_valheim_config:/config alpine sh -c "
  wget -O /config/worlds_local/MidgardWorld.db  'https://UT_URL_FOR_DB' &&
  wget -O /config/worlds_local/MidgardWorld.fwl 'https://UT_URL_FOR_FWL'
"
docker compose restart

SCP Direct Transfer (Alternative)

# From your local machine (skip UploadThing entirely):
scp MidgardWorld.db MidgardWorld.fwl \
  root@YOUR_VPS_IP:/var/lib/docker/volumes/midgard_valheim_config/_data/worlds_local/
ssh root@YOUR_VPS_IP "cd /opt/valheim && docker compose restart"
SERVER OPERATIONS
Day-to-day management of your Valheim server

Monitoring

# Live server logs
docker compose logs -f

# Resource usage
docker stats midgard_valheim

# Backup log
tail -100 /var/log/valheim-backup.log

# Check cron is registered
crontab -l

Updating the Server

# Manual update (the container also auto-updates via UPDATE_CRON)
cd /opt/valheim
docker compose pull
docker compose down && docker compose up -d

Admin Commands

To use admin commands in-game, add your Steam ID to the admin list: 

# Find your Steam ID at steamidfinder.com, then:
echo "YOUR_STEAM_ID_64" >> \
  /var/lib/docker/volumes/midgard_valheim_config/_data/adminlist.txt
docker compose restart

Whitelist & Bans

FilePurpose
adminlist.txtSteam IDs with admin commands access
permittedlist.txtWhitelist — only these Steam IDs can join
bannedlist.txtBanned Steam IDs (blocked from joining)

All files located at: /var/lib/docker/volumes/midgard_valheim_config/_data/

Auto-restart on Reboot

The compose file uses restart: unless-stopped — the server automatically comes back after a VPS reboot. Verify Docker itself starts on boot: 

sudo systemctl is-enabled docker   # should say "enabled"
# If not:
sudo systemctl enable docker
TROUBLESHOOTING
Common issues and how to fix them

Server Not Appearing in Browser

  • Ensure UDP ports 2456–2457 are open: sudo ufw status
  • Connect directly by IP: Add Server → YOUR_IP:2456
  • Check server is running: docker compose ps
  • It can take up to 5 minutes on first launch for the server to register publicly

PlayFab / Crossplay Errors

Known issue: The Linux server occasionally has PlayFab authentication errors. Add SERVER_ARGS: "-crossplay" to the environment in docker-compose.yml or remove it entirely to disable crossplay and resolve the error.

World Generates Fresh (Saves Not Loading)

  • Confirm WORLD_NAME in docker-compose.yml exactly matches your .db / .fwl filenames (case-sensitive)
  • Check files exist: ls /var/lib/docker/volumes/midgard_valheim_config/_data/worlds_local/
  • Ensure both .db and .fwl are present — one without the other will fail

Backup Script Fails

# Check the log for errors
tail -50 /var/log/valheim-backup.log

# Common: UPLOADTHING_API_KEY not set
echo $UPLOADTHING_API_KEY   # should print your key

# Common: jq not installed
sudo apt install -y jq

# Common: worlds path not found — check volume path
docker volume inspect midgard_valheim_config

High CPU / RAM Usage

  • CPU spikes are normal when players explore new areas (world generation)
  • For 6–10 players upgrade to 4 vCPU / 8 GB RAM
  • Mods significantly increase resource usage — budget accordingly
  • Monitor with: docker stats midgard_valheim
